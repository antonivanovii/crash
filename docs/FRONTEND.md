# Фронтенд: Feature-Sliced Design

Правила ниже проверяет линтер (`eslint.config.js`, функция `fsdLayerRules`),
а не ревью. Нарушение — ошибка сборки, не замечание.

## Слои

Сверху вниз, каждый видит только те, что ниже:

```
app        инициализация: провайдеры, роутер, глобальные стили
pages      страницы; единственный слой, который собирает фичи в экран
widgets    самостоятельные блоки UI, составленные из сущностей
features   пользовательские сценарии
entities   бизнес-сущности и их состояние
shared     переиспользуемое без бизнес-смысла: транспорт, layout, утилиты
```

`apps/web/src/<layer>/<slice>/<segment>/`, где segment — `ui`, `model`, `api`,
`lib` или `config`.

## Три правила, которые проверяются автоматически

**1. Зависимости идут только вниз.** `entities` не имеет права импортировать
`features`, `shared` — вообще ничего из приложения.

Импорт снизу вверх делает нижний слой непереносимым: вынести `entities/round`
в другой проект станет невозможно, потому что он тянет за собой конкретную
игру.

**2. Слайсы одного слоя не импортируют друг друга.** `features/play-limbo`
не может импортировать `features/betslip`. Общее выносится слоем ниже.

Импорт вбок превращает набор слайсов в клубок, который нельзя удалить
по частям. Именно поэтому три игровых примитива (`useAtomicBet`,
`useOpenRound`, `useSharedRound`) лежат в `entities/round`, а не в фичах:
их использует каждая игра, и будь они фичей — каждая игра импортировала бы
соседнюю.

**3. Чужой слайс — только через публичный API.** `@/entities/round`, но не
`@/entities/round/model/round.store.js`.

Без этого `index.ts` перестаёт что-либо значить и любой внутренний файл
становится частью контракта.

Исключения по построению: `app` и `shared` не поделены на слайсы — в `app`
лежит инициализация приложения, в `shared` сегменты законно пользуются друг
другом.

## Импорты

Между слоями — только алиас `@/`. Относительный путь на три уровня вверх
запрещён: он скрывает нарушение порядка слоёв за `../../../`.

Внутри своего слайса — относительные пути.

Внешние пакеты (`@kobold/game-engine`, `@kobold/ui`, `react`) доступны везде.

## Где что лежит в этом проекте

```
app/
  providers/       QueryClientProvider, RealtimeProvider
  router/          дерево маршрутов по docs/MAP.md
  RootLayout.tsx   оболочка: хедер, баннеры, Outlet
pages/
  casino-lobby/    лобби
  game/            /casino/$gameSlug + реестр экранов игр
  fairness-verify/ верификатор
  stub/            заглушки заведённых заранее маршрутов
widgets/
  app-header/      навигация, баланс, статус соединения
features/
  play-limbo/      экран Limbo целиком
  betslip/         купон, переживающий навигацию
entities/
  session/         сессия и билет для сокета
  wallet/          баланс из сокета
  round/           состояние раундов + три игровых примитива
  game/            метаданные игр
shared/
  api/             ky-клиент, QueryClient, транспорт реального времени
  model/           состояние связи и смещение часов
  ui/              GameShell, GameFooter, Placeholder
  lib/, config/
```

## Почему реестр экранов игр живёт в `pages/game`

Сущность `entities/game` держит метаданные: слаг, название, вид примитива.
Знать про компоненты она не может — компоненты живут в фичах, а это слой выше.

Реестр `slug → ленивый компонент` — работа слоя `pages`: только он вправе
собирать фичи. Побочный выигрыш: каждая игра остаётся отдельным чанком,
и тот, кто зашёл в Limbo, не тянет код Plinko.

## Три вида состояния разведены

| Что                                    | Где                                 | Почему                                    |
| -------------------------------------- | ----------------------------------- | ----------------------------------------- |
| Серверное: каталог, история, настройки | React Query                         | кеш, инвалидация, ретраи                  |
| Реалтайм: баланс, фаза раунда          | Zustand в `entities/*`              | приходит по сокету, единственный источник |
| UI: купон, фильтры, модалки            | Zustand в `features/*` или локально | не переживает бэкенд                      |

Баланс в React Query приводит к тому, что после ставки он обновляется
с задержкой или не обновляется вовсе. Он живёт в `entities/wallet` и
пишется только из событий сокета.

## Что осталось за рамками правил линтера

Кросс-импорты сущностей в FSD решаются нотацией `@x` (`entities/round/@x/game`).
Здесь они пока не нужны: `GameSlug` берётся напрямую из `@kobold/game-engine`,
и сущности друг о друге не знают. Если понадобится — заводить `@x`, а не
ослаблять правило.
