# Карта фронтенда

## Верхний уровень: три раздела и shell

Оболочка (хедер, кошелёк, сокет-провайдер, авторизация) общая. Три раздела — это три ленивых чанка, загружаются по требованию.

```
/                     редирект на /casino
/casino               свои игры
/sports               спортивная книга
/markets              маркет предсказаний
/wallet               кошелёк
/account              профиль и настройки
/fairness             провably fair
/rules                правила и справка
```

Спортивный раздел с деревом лиг весит много и не нужен тому, кто пришёл в Mines. Разделение на чанки — не микрооптимизация, а разница в секундах первой загрузки на мобильном.

---

## `/casino` — игры

```
/casino                       лобби
/casino/:gameSlug             экран игры
/casino/history               история ставок
/casino/leaderboard           опционально
```

**Лобби.** Секции: продолжить (если есть брошенный открытый раунд), общие игры с живым состоянием (crash — текущий множитель, рулетка — таймер до закрытия ставок), соло-игры, недавно сыгранные. Плюс лента крупных выигрышей, если она нужна как социальный элемент.

Живые превью общих игр — отдельная лёгкая подписка на сводный канал, не на комнаты каждой игры. Иначе лобби открывает семь соединений.

**Экран игры** — единый layout, один и тот же для всех:

```
GameShell
  ├── BetPanel        левая колонка, 232px
  ├── GameCanvas      область игры
  └── GameFooter      nonce, хэш, ссылка на верификатор
```

Игра поставляет три вещи: содержимое панели, компонент отрисовки и хук из рантайма. Мы разобрали десяток экранов — все укладываются в этот каркас, и это не совпадение, а следствие того, что примитивов три.

Слаги: `limbo`, `dice`, `mines`, `towers`, `plinko`, `wheel`, `keno`, `crash`, `roulette`, `dragon-tiger`, `sic-bo`.

**Модалка при заходе с активным раундом.** Игрок бросил Mines на четвёртом шаге и вернулся через день — нужен явный экран восстановления с текущим состоянием и множителем, а не молчаливое подставление доски.

## `/sports` — книга

```
/sports                       главная: ближайшее и популярное
/sports/live                  живые события
/sports/:sport                вид спорта
/sports/:sport/:league        лига
/sports/event/:eventId        карточка события, все рынки
/sports/bets                  мои ставки
/sports/bets/:betId           детали ставки
```

**Дерево навигации** слева на десктопе, в шторке на мобильном. Оно большое и меняется редко — кешировать агрессивно, React Query с долгим `staleTime`.

**Купон — не страница, а персистентный слой.** Живёт поверх любого маршрута: боковая панель на десктопе, снизу sheet на мобильном. Состояние в отдельном сторе, переживает навигацию и перезагрузку (в этом случае с обязательной перепроверкой цен).

Внутри купона:

- Каждое плечо со своей ценой и версией
- Изменение цены — явная подсветка и явный выбор политики (принимать только улучшение / любое / отклонять)
- Ошибки приёма по каждому плечу отдельно
- Итоговая маржа экспресса рядом с коэффициентом, если экспрессы будут

**Карточка события** — вкладки по группам рынков (основные, тоталы, гандикапы, статистика). Живой счёт и статус рынка сверху. Приостановленный рынок должен выглядеть однозначно приостановленным, а не просто некликабельным.

**Мои ставки** — три вкладки: открытые, рассчитанные, возвращённые. У открытой видно, что уже случилось по её плечам. У рассчитанной — источник результата и время расчёта. Это то, что предъявляется при споре.

## `/markets` — предсказания

```
/markets                      список рынков
/markets/:marketId            рынок: график, торговля, история
/markets/portfolio            мои позиции
/markets/:marketId/resolution критерии и разрешение
```

**Экран рынка** — центральный элемент раздела:

- График цены во времени (строится из `q_before`/`q_after` сделок)
- Панель торговли: купить / продать, выбор исхода, ввод суммы, **предпросмотр средней цены и проскальзывания до подтверждения**
- Текущая позиция и нереализованный результат
- Лента сделок
- Критерии разрешения — на видном месте, с хэшем и датой фиксации

Про формат цены — вопрос, который я обещал разобрать. Проценты, центы и коэффициенты — это одни и те же числа, но ведут людей по-разному. Проценты читаются как вероятность и располагают к аналитическому мышлению. Центы читаются как цена актива и располагают к торговле. Коэффициенты читаются как ставка. Для маркета предсказаний я бы взял проценты по умолчанию с переключателем на центы — и не давал коэффициенты вообще, иначе раздел сливается со спортом по восприятию.

**Портфель** — позиции, себестоимость, текущая оценка, реализованный и нереализованный результат. Отдельно — ожидающие разрешения.

---

## `/wallet`

```
/wallet                       обзор
/wallet/deposit
/wallet/withdraw
/wallet/history               выписка из леджера
```

**История** — это выписка, а не список. Каждая строка: тип, сумма, баланс после, ссылка на источник (раунд, ставка, сделка). Фильтр по типу и периоду.

Отдельно должно быть видно **открытые обязательства**: сколько в эскроу активных раундов, спортивных ставок, позиций на рынках. Игрок должен понимать, почему свободный баланс меньше суммы, которую он держит в системе.

---

## `/account`

```
/account/profile
/account/security             пароль, 2FA, сессии
/account/limits               лимиты
/account/notifications
```

**`/account/limits`** — не формальность. Лимит депозита, лимит ставки, лимит времени сессии, самоисключение на период. Ужесточение применяется мгновенно, ослабление — с задержкой в сутки. Это стандартная механика, и она должна быть, раз мы весь разговор обсуждали честность как принцип.

---

## `/fairness` — рабочий раздел

```
/fairness                     как это устроено
/fairness/verify              верификатор
/fairness/seeds               мои сиды, ротация, раскрытые
/fairness/chain               хэш-цепочка общих игр
/fairness/models              полосы и таблицы выплат, хэши моделей
```

Это не сноска в футере, а полноценный раздел. Верификатор пересчитывает результат в браузере вызовом той же функции из `game-engine`, что использовал сервер. Двадцать строк кода — и главный аргумент продукта.

## Компоненты, живущие поверх маршрутов

Не страницы, но требуют места в архитектуре:

| Компонент                     | Поведение                                    |
| ----------------------------- | -------------------------------------------- |
| Купон                         | Персистентный, переживает навигацию          |
| Панель баланса                | Из сокета, единственный источник истины      |
| Тост об изменении цены        | Спортивная секция                            |
| Модалка восстановления раунда | При входе в игру с активным раундом          |
| Индикатор соединения          | Обязателен: crash и рулетка зависят от связи |
| Баннер приостановки           | Когда фид молчит и рынки закрыты             |

---

## Что определяет структуру, а не наоборот

Три момента, из которых карта и выводится:

**Игровой рантайм — три хука, а не тридцать экранов.** `useAtomicBet`, `useOpenRound`, `useSharedRound`. Новая игра это компонент отрисовки плюс функция из engine. Маршрут `/casino/:gameSlug` с реестром игр, а не отдельные маршруты на каждую.

**Один сокет на приложение.** Живёт в провайдере над роутером, подписка на комнаты по монтированию экрана игры. При навигации между играми соединение не пересоздаётся.

**Три вида состояния разведены.** Серверное — React Query. Реалтайм (баланс, фаза раунда, живые цены) — Zustand. UI (купон, фильтры, модалки) — локально или в отдельном сторе. Попытка держать баланс в React Query приводит к тому, что после ставки он обновляется с задержкой или не обновляется вовсе.

## Порядок появления

| Фаза плана | Что появляется                                  |
| ---------- | ----------------------------------------------- |
| 0          | Shell, авторизация, `/wallet`, `/account`       |
| 1          | `/casino/:gameSlug` (Limbo), `/fairness/*`      |
| 2–3        | Лобби с секциями, `/casino/history`             |
| 4          | Живые превью в лобби, индикатор соединения      |
| 7          | Весь `/sports`, купон                           |
| 8          | Весь `/markets`                                 |
| 6          | Админка — отдельное приложение, не в этой карте |

Админку стоит держать отдельным приложением на своём домене: другая аудитория, другие требования к доступу, другой цикл релизов. Смешивать операторские экраны с игровыми — способ однажды показать игроку не то.
